## Keep It Simple Stupid

And here we go again. This is the third time I've put a personal
blog online. And the fifth design attempt... After trying Next,
vanilla JS, HTMx, and seeing that time is a tyrant, I decided to go back to the most
basic of the basic: a static site built with [Jekyll][jekyllrb].

At the end of the day, what I really want is a platform to publish my
content, without being a slave to social media (a topic for another post).
So, armed with Neovim, a little HTML, a few lines of CSS and about 4
hours to mix it all together, here we are again.

This new edition of the blog is 100% about pragmatism: I don't have
as much time as I used to, so building, implementing and
maintaining a system on my other server was completely out of the question. So I
ended up choosing [GitHub Pages][ghpages] to host the site.

Why GitHub Pages? First and foremost, because I wanted to write notes in
markdown files without having to use a database. The previous
version of the blog used [PocketBase][pocketbase], but, _mea culpa_, I over-engineered it:
automatic deploys, GitHub Actions, analytics integration, etc. The second
point is that I no longer have to worry about backups, maintaining domain
names, certificates and everything that comes with running
a server. It strikes me as a good balance between keeping control of my
information and delegating tasks to a third-party
platform.

As time goes by, I'll add new features. I admit it's pretty
bare-bones right now, but _hey!_ at least I can start writing without
having to worry about anything other than the content.

If you're reading this and don't know what I write about, then welcome — and
let me tell you that I like sharing knowledge, opinions and tutorials
about **Linux, programming, AI, keyboards and technology** in general.

If you already know me, then thanks for sticking around!
